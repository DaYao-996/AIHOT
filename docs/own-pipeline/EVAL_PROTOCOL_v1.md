# 新留出前的评估口径 v1

日期：2026-11-18。这是新文件。它冻结以后才能使用的列和分母。它不是生产线标准，也没有被批准为验收通过。80%、70/55/40 和 A–F 都不是本文件的通过线。

在按本口径写完独立标签之前，不要开正式新留出，也不要报告准确率。

## 每条样本分开的列

这些列不能并成一个分数或一个「可发」。

| 列 | 允许值 | 含义 |
| --- | --- | --- |
| 缺料 | `complete`、`missing_body`、`missing_quote`、`missing_article_body` | 原料齐不齐。缺了就停在缺料，不能改叫低价值 |
| 事实 | `unchecked`、`source_claim`、`checked` | 来源这样说，不等于已经核对 |
| 价值 | `not_judged`、`low`、`candidate`、`abstain` | 人给的对照标签。没有批准的分数线可以把某分自动写成 `low` 或 `candidate` |
| 许可 | `not_licensed`、`licensed_by_human` | 只有人能标成许可。模型和规则函数不能写 `licensed_by_human` |
| 角色 | `positive`、`negative`、`repair`、`dispute`、`abstain` | 独立标签。`dispute` 不并进金标 |

当前代码里的判断表只强制了缺料、事实、`reference_only` 和 `not_licensed`。价值列里的 `low` / `candidate` 还没有实现，避免把未批准的分数写进库。

## 分母

正例分母 = 独立标成 `positive` 的全部样本。

下面几种仍留在分母里，并另计人数：

- 系统弃权（`abstain` 或没有判断）
- 缺料
- 事实仍是 `unchecked` 或 `source_claim`
- 价值标成 `not_judged`

分子只计进入约定候选队列、且缺料列不是缺失、事实列不是把未核对写成已核对的正例。弃权不能从分母拿掉。全退成待核不算通过。

硬错误是另一列：独立标成 `negative` 的样本进了推荐队列，或者缺料/未核对被标成可许可。本文件不宣布硬错误为 0。

争议（`dispute`）单独列表，不拿来凑分子或分母。无独立裁决之前保持争议。

每次报告要写分子、分母、弃权条数、争议条数和样本从哪来。样本内的计数不是总体结论。
